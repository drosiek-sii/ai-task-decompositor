# AEM Scaffold Demo (NOT runnable)

This directory is a **structural mock-up only**. It exists so a reader can see what the AEM artifacts produced by [`examples/QANTAS_PAGE_MIGRATION_PLAN.md`](../QANTAS_PAGE_MIGRATION_PLAN.md) would look like on disk — file paths, JCR namespaces, dialog shape, Sling Model shape, HTL skeletons.

## What this is NOT

- **Not buildable.** There is no `pom.xml`, no parent reactor, no AEM SDK dependency. `mvn install` will not work.
- **Not deployable.** Even if you wired it into a real `aem-project-archetype` reactor, the dialogs reference resource types and clientlibs that don't exist here.
- **Not authoritative.** The XML is hand-edited, not generated by the archetype. A real project should always start from the official `mvn archetype:generate -D archetypeArtifactId=aem-project-archetype` and only deviate where necessary.
- **Not exhaustive.** Several tasks are "wire X into template structure"; instead of duplicating the same file across tasks, they share one annotated `structure/.content.xml` with comments showing where each task's contribution would go.

## What this IS

- A side-by-side reference for what each task in [Beads](#mapping) would touch.
- A pattern walk-through for someone who hasn't built AEM components before — page component, dialog, Sling Model, HTL partial, custom component, Experience Fragment.
- Compatible with reading in any IDE; XML is annotated; Java compiles syntactically (would need real AEM uber-jar to actually run).

## How a real AEM project would consume this

1. Run `mvn archetype:generate -DarchetypeGroupId=com.adobe.aem -DarchetypeArtifactId=aem-project-archetype -DarchetypeVersion=...` to bootstrap a real reactor with `core/`, `ui.apps/`, `ui.content/`, `dispatcher/`, `it.tests/`.
2. Drop the package paths from this demo into the equivalent reactor modules:
   - `core/src/main/java/...` → real `core` module
   - `ui.apps/src/main/content/jcr_root/...` → real `ui.apps` module
   - `ui.content/src/main/content/jcr_root/...` → real `ui.content` module
3. Wire dependencies in each `pom.xml`: AEM SDK API, Sling Models API, Sling Models annotation processor.
4. Build: `mvn clean install -PautoInstallSinglePackage` against a running AEM author at `localhost:4502`.

## Required tooling for actual AEM dev (none of which is set up here)

- JDK 11 or 17
- Maven 3.6+
- AEM as a Cloud Service SDK (or AEM 6.5 Quickstart) — commercial Adobe license
- AEM author + publish instances running locally
- Optional: `mvn -Pclassic` for AEM 6.5; `-Pcloud` for AEMaaCS
